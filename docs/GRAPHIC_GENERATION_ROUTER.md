# Graphic Generation Router

## 1. Введение и назначение
Graphic Generation Router определяет оптимальный инструмент для визуализации информации. Он предотвращает нерациональное использование дорогостоящих или неподходящих генеративных моделей (например, генерацию схем через текстовый prompt в Image Gen) и направляет задачу на наиболее эффективный движок.

---

## 2. Матрица выбора инструментов

В зависимости от характера графической задачи выбирается один из подходов. **Конкретные модели не фиксируются в документации; выбор осуществляется по доступным моделям на момент вызова.**

| Инструмент | Когда использовать (Применение) | Когда НЕ использовать | Ожидаемый формат вывода |
| :--- | :--- | :--- | :--- |
| **GPT Image / OpenAI Images API** | Высокохудожественные иллюстрации, концепт-арт, фотореалистичные изображения, логотипы. | Текст, точные схемы, UI/UX интерфейсы, диаграммы связей. | URL-ссылка на сгенерированную картинку (.png/.jpg) |
| **Nano Banana / Gemini Image** | Простые быстрые изображения, абстрактные фоны, иконки, текстуры. А также: **image editing** (редактирование по референсу), **reference-based generation**, **character/object consistency** (сохранение персонажа), **multi-image fusion** (слияние изображений), **style series** (серии в одном стиле). | Сложный встроенный текст, точные чертежи. | Локальный путь или URL (.png/.jpg) |
| **Research / Brief Layer (NotebookLM)** | Как вспомогательный слой исследования и генерации брифов для сложных медиа-задач. | Как основной генератор готовых презентаций или слайдов. | Текстовый бриф, выжимка, структура проекта |
| **Не-image инструменты** (Mermaid, SVG, HTML) | Диаграммы классов, блок-схемы, архитектура систем, графики, UI-макеты, таймлайны, таблицы, точный текст. | Реалистичные фото, художественный арт. | Текстовый код Mermaid, SVG-код или HTML-артефакт |

---

## 3. Цепочка генерации презентаций (Presentation Chain)
**Запрещено** использовать NotebookLM или сырые генераторы картинок как основной инструмент сборки презентаций. Для создания презентаций применяется следующая цепочка:
1. **Research Brief**: Исследование предметной области и сбор фактов (здесь может применяться NotebookLM).
2. **Outline**: Создание текстовой структуры слайдов и тезисов.
3. **Slides / HTML / PPTX**: Программное создание структуры презентации (HTML/CSS-артефакт или PPTX-скрипт).
4. **Visual Elements (Image Model)**: Использование генераторов картинок исключительно для создания фонов или иллюстраций к слайдам, но не самих слайдов целиком.

---

## 4. Правила выбора не-image инструментов
Если визуализация носит структурный, логический или текстовый характер (нужен точный текст, таблицы, схемы, интерфейсы или диаграммы), **запрещено** использовать генераторы картинок. Вместо этого применяются:
1. **Mermaid.js**: Для блок-схем, диаграмм последовательностей (Sequence diagrams), диаграмм классов, ER-диаграмм, диаграмм Ганта.
2. **Инлайновый SVG (HTML/SVG)**: Для кастомных дашбордов, простых иконок, кастомных mindmap с красивым оформлением.
3. **HTML/CSS (Claude Design)**: Для макетов сайтов, интерфейсов приложений, интерактивных графиков на JS (p5.js).

---

## 5. Шаблон графического брифа (Image Brief)
Перед вызовом любого генератора картинок (GPT Image, Nano Banana) агент должен составить внутренний бриф:

```json
{
  "target_tool": "gpt_image | gemini_image | mermaid | html_svg",
  "prompt_details": {
    "subject": "Основной объект изображения",
    "style": "Стиль (flat vector, photo, 3d render, schematic diagram)",
    "palette": "Цветовая гамма (dark theme, pastel, monochrome)",
    "text_elements": "Требуемый текст внутри (если есть — минимизировать для image-моделей)"
  },
  "aspect_ratio": "landscape | square | portrait",
  "reference_image": "URL или путь к референсу (для image editing / consistency)",
  "consistency_rules": "Правила сохранения стиля/персонажа для серии картинок",
  "fallback_plan": "Что делать, если генерация упадет с ошибкой (например, использовать SVG-схему)"
}
```

---

## 6. Матрица проверки качества (Quality Gate)

Перед показом изображения пользователю, агент проводит мысленную или визуальную проверку:

1. **Читаемость текста**: Если на картинке должен быть текст, не искажен ли он? (Если искажен — перегенерировать или заменить на SVG/HTML).
2. **Артефакты**: Нет ли лишних конечностей, размытых областей, несвязанных элементов?
3. **Соответствие палитре**: Соответствует ли тема (светлая/темная) запросу пользователя?
4. **Формат и доступность**: Лежит ли файл по доступному локальному пути или внешней ссылке, готов ли Markdown-тег `![описание](url-или-путь)` для рендеринга в Telegram?
