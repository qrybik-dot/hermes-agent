1. Главный вывод

Текущий routing не ломаем
Flash Low остаётся базовой моделью. GPT‑5.5 остаётся инженером для кода и VPS. Gemini Pro остаётся на сложном research до настоящего A/B.
Запускаем два контролируемых пилота
Flash Agent для read-only и обратимых многошаговых задач. Sonnet для части expert_analysis, planning и reviewer.

Flash Agent доказал скорость на длинном контексте и завершил реальный многофайловый workflow.

Sonnet был быстрым в коде и дал наиболее подробную стратегию контроля качества.

Ни одна модель не доказала право заменить остальные глобально.

Решение: внедрение новых primary-маршрутов пока не делать. Сначала 20–30 реальных задач с логированием, сравнением и быстрым откатом.

Простой workflow
Flash Low и Flash Agent оба получили 100/100. Flash Low 16,1 сек, Flash Agent 16,8 сек. На короткой цепочке Agent не выиграл.
Multi-file workflow
Flash Agent прочитал 3 файла, применил правила, сопоставил владельцев, отсортировал события и записал JSON + Markdown. 100/100, 25,9 сек.

Flash Agent действительно способен завершить последовательность tool calls.

Pro Agent не прошёл идентичный multi-file сценарий; подтверждён только function call и статические задачи.

8. Экспертная дилемма

Gemini Pro
Выбрал ограниченный пилот, предложил 15 задач и практичный rollback. Слабость: неверно понял поле failure domain как область разрешённых задач.
Sonnet
Дал более глубокие метрики, p50/p95, stop conditions и межканальные риски. Слабость: предложил 200 задач, что избыточно для текущего масштаба.

Итог: Sonnet полезнее как эксперт и reviewer, но его планы нужно ограничивать размером, сроком и бюджетом. Gemini Pro практичнее, но может недораскрыть архитектурный риск.

11. Что тест не доказал

Скорость GPT и Antigravity нельзя сравнивать напрямую: GPT запускался через полный Codex runtime.

Один кодовый модуль не измеряет качество рефакторинга большого репозитория.

Точный поиск фактов в длинном тексте не равен глубокому исследованию.

Smoke и function call не доказывают надёжность 30-шагового agentic workflow.

Автоматическое переключение primary-моделей пока не оправдано.

Финальный вердикт: сохранить текущий routing, подготовить измеряемый пилот Flash Agent и Sonnet, после 20–30 реальных задач принять решение по данным.
