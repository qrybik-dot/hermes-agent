1. Краткий вывод

Рабочая схема сейчас

Эксперимент не включён автоматически
agentic и long_context_extract прописаны в конфиге, но agentic_enabled=false и long_context_split=false. Ручная проверка доступна через /role agentic и /role long_context_extract.
Практический смысл: Hermes не тратит дорогую или медленную модель на простые сообщения, не отдаёт VPS-операции экспериментальному агенту и не делает скрытый fallback в случайную бесплатную модель.

2. Принцип выбора модели

КритерийЧто делает HermesЗачем
Тип задачиЧерез regex/детерминированный классификатор выбирает роль: simple, research, expert_analysis, coding, server_debug и т.д.Не тратить LLM-вызов на классификацию и не зависеть от случайного решения модели.
Риск задачиVPS, systemd, git, sudo, код и конфиги уходят в server_debug или coding.Изолировать опасные действия от универсального agentic-режима.
Нужные инструментыРоль получает только свои toolsets: simple часто no_mcp, coding получает terminal/file/tests, agentic не получает terminal.Меньше лишних tool calls, ниже риск поломки.
Качество против скоростиПростое идёт на Flash Low, анализ и research на Pro Low, код/VPS на GPT‑5.5 Codex.Сохранить быстрые ответы без потери качества на сложных задачах.
FallbackРазрешён максимум один квалифицированный fallback, часто только до первого tool-call и с изолированным контекстом.Не плодить цепочки провайдеров, не переносить секретный/аккаунтный контекст наружу.

4. Как проходит один запрос

1. classify_task
Проверяет slash override, no_llm commands, длину текста, VPS/code/research/expert/planning/parser/long-context признаки.
2. route_turn
Добавляет флаги намерений: travel, calendar, email, memory, report, Context7, skills, NotebookLM. Может подгрузить skill.
3. resolve config
По роли берёт model_roles[role], провайдера и runtime. Затем строит fallback-chain.

Travel и calendar остаются специализированными flow: agentic не должен их забирать.

Для risky/large задач включается адаптивное планирование и reviewer/delegation, если это уместно.

В логах фиксируется task_role, selected_provider, selected_model, routing_reason, toolsets, max_iterations.

5. No-secret YAML как у нас

Ниже не полный production-конфиг, а безопасный фрагмент, достаточный для повторения логики.

model:
  default: gemini-3.5-flash-low
  provider: custom
  base_url: http://127.0.0.1:8317/v1
  context_length: 64000

model_roles:
  simple:
    provider: custom
    model: gemini-3.5-flash-low
  parser:
    provider: custom
    model: gemini-3.5-flash-low
  research:
    provider: custom
    model: gemini-3.1-pro-low
  expert_analysis:
    provider: custom
    model: gemini-3.1-pro-low
  long_context:
    provider: custom
    model: gemini-3.1-pro-low
  planning:
    provider: openai-codex
    model: gpt-5.5
  coding:
    provider: openai-codex
    model: gpt-5.5
  server_debug:
    provider: openai-codex
    model: gpt-5.5
  agentic:
    provider: custom
    model: gemini-3-flash-agent
  long_context_extract:
    provider: custom
    model: gemini-3-flash-agent
  no_llm:
    provider: none
    model: no_llm

routing_policy:
  deterministic_classifier: true
  separate_llm_classifier_call: false
  silent_free_fallback_for_quality_locked_roles: false
  max_model_fallbacks: 1

routing_experiments:
  agentic_enabled: false
  long_context_split: false
  pilot_mode: manual_only

Защитный fallback для agentic/extract

role_fallbacks:
  agentic:
    public:
      - provider: openai-codex
        model: gpt-5.5
        reasons: [rate_limit, upstream_rate_limit, usage_limit_exhausted, auth, auth_permanent, billing, model_not_found, provider_policy_blocked, overloaded, server_error, timeout]
        only_before_tools: true
        isolate_context: true
        allowed_tools: []
    sensitive: same_as_public
  long_context_extract:
    public: same_as_agentic
    sensitive: same_as_agentic
Важно: не копировать секреты, токены и весь production config.yaml в отчёты или Git. Для документации использовать только no-secret overlay.

7. Почему выбраны именно эти модели

Flash Low как default
Он быстрее, достаточно точен для простых и parser-задач, меньше провоцирует лишние шаги. Замена на agent-модель не дала выигрыша.
Gemini Pro Low для анализа
Лучше подходит для research, long-context и прожарок, где важнее устойчивое рассуждение, чем минимальная задержка.
GPT‑5.5 для кода и VPS
Выбран не как быстрый default, а как специализированный исполнитель для репозитория, тестов, серверного debug и сложных правок.
Sonnet/Opus не стали default
Sonnet полезен как fallback/reviewer, Opus Thinking оставлен для ручной критической эскалации. Для рутины это лишняя стоимость, задержка и риск переусложнения.
Прожарка решения: текущая схема консервативная и поэтому правильная для VPS с 1 GB RAM и production-ботом. Слабое место — много regex-логики: её надо покрывать тестами и логами, а не лечить «ещё одной умной моделью».

8. Как настроить так же

  1. Зафиксировать baseline. Сохранить текущий config.yaml, ветку/commit, status сервисов и rollback tag.
  2. Добавить no-secret overlay. Внести model_roles, routing_policy, routing_experiments и role_fallbacks без изменения секретов.
  3. Оставить эксперименты выключенными. Для первого запуска поставить agentic_enabled=false, long_context_split=false, pilot_mode=manual_only.
  4. Проверить резолв ролей без gateway restart. Запустить Python-smoke на route_turn и _resolve_turn_agent_config.
  5. Перезапустить один раз только при изменении runtime-конфига. После restart проверить systemctl show, логи task routing и ручные /role agentic.
  6. Автофлаги включать по одному. Сначала long_context_split для узкого извлечения, потом agentic_enabled для безопасных многошаговых задач. У нас оба пока выключены.
  7. Откат держать простым. Быстрый откат — вернуть оба флага в false; глубокий — restore backup config или git tag.

10. Риски и ограничения

Regex-роутинг требует ухода
Он быстрый и предсказуемый, но новые пользовательские формулировки могут попадать не туда. Нужны regression-тесты на реальные сбои из Telegram.
Benchmark не равен production
Автотесты были sandboxed и без production data. Это хорошо для безопасности, но не доказывает поведение на всех реальных задачах.
Опасно включать agentic глобально
Flash Agent не доказал преимущество над Flash Low, поэтому автофлаг без 20–30 реальных задач был бы хуже текущего решения.
Fallback нужно держать коротким
Один fallback — правильное ограничение. Длинная цепочка моделей увеличит задержку и риск потери контекста.

12. Техническое приложение

Файлы и артефакты, на которых основан отчёт
  • /home/hermes/.hermes/config.yaml — live-конфиг, прочитан с редактированием секретов.
  • /home/hermes/hermes-v018-integration/gateway/task_router.py — классификация ролей, toolsets, experiment flags.
  • /home/hermes/hermes-v018-integration/gateway/run.py — resolve модели по роли и fallback-chain.
  • /home/ubuntu/MODEL_QUALIFICATION_FINAL.md — итоговая квалификация моделей от 2026-07-04.
  • /home/ubuntu/model_routing_autotest_results.json — сравнительные тесты моделей.
  • /home/ubuntu/agentic-pilot-evaluation-summary.json — agentic-пилот и решение не промотить.
  • /home/ubuntu/MODEL_ROUTING_SAFE_ROLLOUT.md — rollout, stop conditions и rollback.
  • /home/ubuntu/check_live_routing_manual.py, /home/ubuntu/verify_live_model_routing_config.py — live-smoke проверки.
Stop conditions для будущего включения agentic
  • agentic перехватил travel/calendar/coding/server request.
  • Любая попытка destructive action без подтверждения.
  • Completion ниже 90% или correction/error rate выше 10%.
  • Рост 429/timeouts у Antigravity/CLIProxyAPI.
  • Регресс Telegram UX, памяти, календаря или travel.
Мини-вывод для будущего решения

Лучший следующий шаг — не включать agentic автоматически сейчас. Сначала собрать 20–30 реальных задач в manual-only, сравнить с Flash Low по задержке, лишним tool calls, точности и числу пользовательских исправлений. Только после этого включать один флаг, не оба сразу.
