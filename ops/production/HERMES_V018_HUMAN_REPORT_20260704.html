6. Как работает fallback

Основная модель→1 повтор при допустимой ошибке→не более 1 fallback→честный итог или blocker

Когда fallback разрешён

Rate limit, исчерпание лимита подписки, проблемы авторизации, billing status, model not found, перегрузка, server error, timeout, format error и другие подтверждённые provider errors.

Защита coding и server debug

Fallback на Gemini для coding/server debug разрешён только до первого tool-call. Контекст изолируется, инструменты отключены. Это не даёт второй модели продолжить опасную серверную операцию, не зная точного состояния после действий первой модели.

Почему fallback только один

Чтобы Hermes не ходил по длинной цепочке слабых моделей, не терял контекст, не создавал повторные действия и не скрывал реальный blocker.

7. Как Hermes теперь узнает о новых моделях

Antigravity проверяется отдельно
Hermes сохраняет live-список Gemini и Claude из CLIProxy.
Codex проверяется отдельно
Hermes получает live-каталог моделей, доступных именно по текущей ChatGPT/Codex подписке.

Если появилась новая модель

Hermes определяет, какая модель добавилась.

Предлагает роли для теста: simple, planning, coding, long context или critical review.

Отправляет одно дедуплицированное уведомление в Telegram.

Предлагает точечную замену после проверки.

Production-маршрутизация не меняется автоматически.

Если активная модель исчезла

Уведомление становится срочным. Hermes показывает, какие основные или fallback-роли затронуты. До решения работает уже настроенный runtime fallback.

Обязательный тест новой модели

1. Ответ
Точный короткий response marker.
2. Инструмент
Безопасный file-tool call.
3. Надёжность
Latency, timeout и fallback.
4. Сравнение
Качество против текущей модели этой роли.
5. Решение
Конкретное предложение: заменить, оставить fallback или не использовать.
6. Approval
Только после подтверждения меняется production config.
Почему не включено полное автоматическое переключение
Новая модель может быть быстрее, но хуже работать с инструментами, иметь другой лимит контекста, нестабильный entitlement или неожиданные ошибки. Поэтому автоматизированы обнаружение, анализ и предложение. Само изменение primary/fallback остаётся контролируемым.

11. Что произойдёт дальше

После trigger будет проверен LastTrigger, exit status, journal и отсутствие лишнего Telegram-сообщения.
При нормальном результате

Дальнейшая работа с новыми моделями

Когда подписка начнёт показывать более новую модель, Hermes не будет ждать ручного обнаружения ошибки. Он увидит изменение каталога, сообщит, какая модель появилась или исчезла, покажет затронутые роли и предложит безопасный план теста и замены.

Итог: система теперь не привязана навечно к сегодняшним названиям моделей. Она умеет заметить обновление модельного ряда и подготовить решение, но сохраняет контроль над production-маршрутизацией.
